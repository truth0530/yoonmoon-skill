# 윤문 (yoonmoon-ko)

한국어 사용자 화면·안내문의 문장을 **읽는 사람이 한 번에 이해하도록** 고친다.
핵심은 문장이 **프로그램이 그렇게 동작한다는 사실**인지, **사용자에게 그렇게 하라는 지시**인지가 한눈에 드러나게 하는 것이다.

## 언제 쓰나
- 화면 문구, 팝업(모달), 툴팁, 튜토리얼, 앱 안 설명서, 메일·공지 초안의 말투를 고칠 때
- 사용자가 "AI가 쓴 것 같다", "무슨 뜻인지 모르겠다", "~않습니다가 헷갈린다"고 할 때
- 긴 문장을 줄바꿈·들여쓰기로 읽기 쉽게 만들 때

## 절대 원칙
1. **의미를 바꾸지 않는다.** 사실을 지시로, 지시를 사실로 바꾸지 않는다. 뜻이 불분명하면 고치지 말고 질문 목록에 올린다.
2. **사실과 지시를 구분한다.** 동작 설명은 결과·수동 형태(「~됩니다」「~에서 빠집니다」), 사용자 행동은 분명한 명령형(「~하세요」「~하지 마세요」「~하면 안 됩니다」).
3. **현재 상태만 쓴다.** 「예전에는」「바뀌었습니다」「더 이상」 같은 이력 문구를 넣지 않는다.
4. **번역투를 쓰지 않는다.** 주어와 동사를 되살려 누가 무엇을 하는지 바로 보이게 쓴다(`references/rules.md` 4절).
5. 합쇼체(「~합니다」)로 통일하고, AI가 작업 의지를 말하는 듯한 동사(「고칩니다」「살핍니다」「지킵니다」)는 담백하게 바꾼다(9절).

## 작업 순서
1. **전수 조사**: 대상 범위에서 문제 표현을 모두 찾아 표(파일:줄, 현재 문구, 유형, 사실/지시)로 만든다. 코드 주석과 사용자에게 보이는 문구를 구분하고, 주석은 건드리지 않는다.
2. **분류**: 각 문장을 사실/지시/라벨(화면에 보이는 이름)로 나눈다. 라벨은 문장과 달리 짧은 명사형 이름이 필요하다.
3. **교체**: `references/rules.md`의 규칙대로 고친다. 한 번에 한 유형씩 처리하면 검수가 쉽다.
4. **동기화**: 문구를 글자로 비교하거나 인용하는 곳(설명서 인용, 시험 기대, 용어집)을 같은 문구로 맞춘다.
5. **검수**: `references/checklist.md`로 남은 문제를 grep하고, 전/후 표와 판단이 필요한 항목(질문 목록)을 보고한다.

## 보고 형식
- 고친 곳 전/후 표 (파일:줄, 전, 후, 유형)
- 고치지 않고 남긴 곳과 이유(의미가 불분명하거나 라벨인 경우)
- 사용자 결정이 필요한 질문(라벨 이름 후보 등)
