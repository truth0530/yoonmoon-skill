# 윤문 규칙

## 1. 「~않습니다」를 피한다
「~않습니다」는 "그렇게 되지 않는다(사실)"인지 "그렇게 하지 말라(금지)"인지 알기 어렵다.

| 의도 | 쓰는 말 | 예 |
|---|---|---|
| 금지·주의(지시) | 「~하면 안 됩니다」「~하지 마세요」 | 「이 칸에는 이름을 적지 마세요.」 |
| 사실(동작) | 「~되지 않습니다」「~에서 빠집니다」「없습니다」 | 「제외한 접수는 보고서에서 빠집니다.」 |
| 가능 여부 | 「~할 수 없습니다」(이유가 있을 때) | 「저장 중에는 닫을 수 없습니다.」 |

## 2. 「세다」 계열을 쓰지 않는다
「센다·셉니다·세지 않는다·세는」은 AI가 쓰는 순우리말 표현이고 공식 용어로 쓰이지 않는다. 「센다/세지 않는다」는 설계된 동작인지 사용자 지시인지도 알기 어렵다.

| 의도 | 쓰는 말 |
|---|---|
| 사실 | 「집계됩니다」「집계에서 빠집니다」「카운트됩니다」 |
| 지시 | 「집계에 넣으세요」「집계하지 마세요」 |
| 부득이하게 「세다」를 써야 할 때 | 지시형만: 「세지 마세요」「세면 안 됩니다」「세어 주세요」 |

화면에 보이는 **라벨**(예: 표의 「세지 않음」)은 「집계 안 함」처럼 짧은 이름이 필요하므로 후보를 제안하고 사용자가 정한다.

## 3. 어색한 자동사·피동
- 「숨습니다」→「숨겨집니다」 (화면 요소가 스스로 숨는 것이 아니라 숨겨지는 것)
- 「접습니다/펼칩니다」처럼 주어가 불분명하면 누가 하는지 드러낸다: 「접힙니다」「펼쳐집니다」, 사용자가 하는 것이면 「접으세요」
- 「~이 보여집니다」(이중 피동)→「~이 보입니다」

## 4. 번역투와 군더더기
| 피할 말 | 고친 말 |
|---|---|
| 「~을 위에 둡니다」 | 「~을 먼저 봅니다 / ~을 위쪽에 표시합니다」 |
| 「~에 의해 ~됩니다」 | 「~가 ~합니다」 |
| 「~를 가지고 있습니다」 | 「~가 있습니다」 |
| 「~하는 것이 가능합니다」 | 「~할 수 있습니다」 |
| 「~에 대하여/대해서」 남용 | 조사로 줄이기 |
| 「~를 통해」 남용 | 「~로」「~에서」 |
| 단위 없는 숫자 「39/39칸」 | 「39칸 중 39칸」 |
| 임의로 만든 용어 | 사용자가 쓰는 정식 용어만 사용 |

## 5. 조사·띄어쓰기 오류
템플릿 문자열에서 받침에 따라 조사가 달라지는 말에 주의한다.
- 「배정를」→「배정을」, 「조건는」→「조건은」
- 변수가 들어가는 문장은 「~을(를)」 대신 문장을 다시 써서 조사가 필요 없게 만든다.

## 6. 이력 문구 금지
화면·설명서·배포물에는 현재 동작만 쓴다.
- 쓰지 않는 말: 「예전에는」「이전 버전에서는」「더 이상 ~하지 않습니다」「바뀌었습니다」「(구)」
- 이력은 변경 이력 문서나 코드 주석에만 둔다.

## 7. 줄바꿈·들여쓰기 (팝업, 튜토리얼, 긴 안내)
- **한 문장 한 줄**이 기본. 길면 의미 단위로 나눈다.
- 문단 사이에 빈 줄 하나.
- 절차는 번호(`1. `), 병렬 항목은 글머리(`· `). 둘째 줄부터 **내어쓰기**(hanging indent).
- 한 단계(또는 팝업 본문)는 3~6줄을 권장한다.
- 줄 간격 1.6 안팎, 본문 폭 34~36em 안팎, 긴 목록은 스크롤.
- 코드에서는 문자열을 `\n`·`· `·`1. ` 규칙으로 문단·목록 요소로 바꾸는 순수 함수를 두고, 텍스트는 `textContent`/이스케이프로만 넣는다.

## 8. 일관된 용어
같은 개념은 한 이름으로 쓴다. 용어집을 한 곳(정본)에 두고 화면은 그 정의를 가져다 쓴다. 문자열을 복사해 붙이지 않는다.
